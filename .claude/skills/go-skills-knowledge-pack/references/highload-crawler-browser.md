# High-load Crawler / Browser Automation

## Default lane

```text
input jobs
  -> allowlist / policy check
  -> bounded queue
  -> errgroup with SetLimit
  -> host-level rate limiter
  -> shared http.Client
  -> parse / classify
  -> durable result sink
  -> metrics + audit log
```

## Modules

- `net/http`: default HTTP client/server.
- `golang.org/x/time/rate`: token bucket limiter.
- `github.com/cenkalti/backoff/v5`: retry backoff.
- `github.com/gocolly/colly/v2`: crawler abstraction.
- `github.com/chromedp/chromedp`: Chrome DevTools Protocol automation.
- `github.com/go-rod/rod`: browser automation alternative.
- `github.com/valyala/fasthttp`: measured hot path only.
- `github.com/hashicorp/go-retryablehttp`: convenient retry HTTP, Watch due v0.x and security history.

## HTTP Transport tuning

Tune by target class:

```go
tr := &http.Transport{
    MaxIdleConns:        2048,
    MaxIdleConnsPerHost: 64,
    MaxConnsPerHost:     128,
    IdleConnTimeout:     90 * time.Second,
    TLSHandshakeTimeout: 10 * time.Second,
}
client := &http.Client{Transport: tr, Timeout: 30 * time.Second}
```

Use concrete numbers only after measuring target behavior.

## Browser escalation policy

Use browser/CDP only when needed:

- JS-rendered DOM
- SPA forms
- CSRF token generated by JS
- screenshot/PDF/visual QA
- network interception

Do not use Chrome for every URL. Keep a separate bounded browser queue.

## Safety

For high-volume crawling or form submission, require:

- ownership/permission/allowlist,
- rate limit,
- robots/legal/contract review where applicable,
- audit log,
- idempotency and retry classification,
- kill switch.
