## 1. JSON-RPC 2.0 transport

`stealth-mcp` speaks line-delimited JSON-RPC 2.0 over `stdin` / `stdout`. Each request is a single JSON object on one line; each response is a single JSON object on one line. Blank lines are tolerated as keepalives.

Supported methods:

| Method | Purpose |
|---|---|
| `initialize` | Client/server handshake; returns server name, version, protocol. |
| `notifications/initialized` | Client-side notification; no response. |
| `tools/list` | Enumerate all 16 tools with their inputSchema and outputSchema. |
| `tools/call` | Dispatch a tool by name; arguments validated against inputSchema. |

Response envelope on success:

```json
{
  "jsonrpc": "2.0",
  "id": <RpcId>,
  "result": { ... }
}
```

Tool-level failures are returned inside `result.structuredContent.error` as an `ErrorEnvelope` (see §3). JSON-RPC `error` is reserved for transport-level failures (parse error, method not found, invalid params).

Server identity:

- `serverInfo.name`: `stealth-mcp`
- `serverInfo.version`: workspace `Cargo.toml` package version (`CARGO_PKG_VERSION`).
- `protocolVersion`: `2024-11-05`

## 3. ErrorEnvelope and ErrorKind

Every tool failure surfaces as an `ErrorEnvelope` carried under `result.structuredContent.error` on the JSON-RPC response. The envelope is a closed contract — exactly **26** `ErrorKind` variants are emitted across the stealth-* boundary, and the set never grows without a deliberate breaking change.

Envelope shape:

```json
{
  "kind": "<snake_case ErrorKind>",
  "message": "<safe-to-log human text>",
  "retryable": false,
  "hint": "<optional operator hint>",
  "retry_after_ms": null
}
```

### 3.1 26 ErrorKind variants

| # | Wire name | When emitted | Retriable | Hint |
|---|---|---|---|---|
| 1 | `aup` | Acceptable Use Policy violation (site / robots / contract). | no | Confirm target is on the AUP allowlist and robots.txt allows the path. |
| 2 | `ssrf` | Server-Side Request Forgery guard tripped (private/internal target). | no | Do not request loopback / RFC1918 / link-local targets. |
| 3 | `vpn_leak` | VPN / egress IP leak detected — real IP would have been exposed. | yes | Bring VPN up and re-run `doctor`; rotate via `vpn_rotate`. |
| 4 | `rate_limit` | Per-host or global rate limit exceeded. | yes | Honor `retry_after_ms`; reduce per-host QPS. |
| 5 | `timeout` | Operation exceeded its timeout budget. | yes | Retry with a larger budget or after backoff. |
| 6 | `captcha` | Captcha challenge encountered and not bypassable in current mode. | no | Switch to an authenticated flow or solve out-of-band. |

## 4. Runtime invariants

### 4.1 Rate limit

Per-host QPS is enforced inside `stealth-cli`. When the limit is exceeded, the tool returns `kind="rate_limit"` with a populated `retry_after_ms`. Callers MUST honor the hint before retrying; retrying earlier is itself a rate-limit violation.

### 4.2 Idempotency

`spider`, `relocate`, and `cf_evaluate` are idempotent given the same `session_id` + arguments — repeated calls return the same `session_id` and converge on the same recipe. `auth_login_*` session tokens are **single-use**: calling `auth_login_complete` a second time with the same token returns `kind="auth_session_not_found"`.

### 4.3 Sessions

`session_id` is a UUIDv4 issued by `spider` (or supplied by the caller) and persisted with VPN binding + recipe hits + optional auth profile reference. `session_show` returns this metadata — cookie values and other secrets are **never** disclosed by any tool, including `auth_*`.

### 4.4 AUP and SSRF

Every URL-bearing tool validates the target against the AUP allowlist (`policy.toml`) and the SSRF guard (private/internal ranges blocked). Violations surface as `kind="aup"` or `kind="ssrf"` and are non-retriable.
