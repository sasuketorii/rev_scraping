## Where rev_scraping loses / ties today

- **vs Browserless / Bright Data**: no bundled CAPTCHA solver; no managed
  dashboard; SaaS sign-up beats a local install on time-to-first-scrape.
- **vs Bright Data / obscura-bridge / Scrapling**: no TLS-fingerprint
  tier-2 yet (v1.4 Lane L).
- **vs Playwright MCP / Puppeteer**: no generic "click any button" surface
  — narrower by design.
- **vs Crawl4AI**: no bundled `LLMExtractionStrategy` (in rev_scraping the
  LLM is the caller, not a pipeline stage).
- **vs Puppeteer**: smaller ecosystem of community recipes / examples.

## Where rev_scraping wins today

- One-binary install. No Node, no Python, no Playwright bundle.
- MCP schema with a 2-major-version compatibility guarantee.
- 26 individually-documented error variants with a `doc_url` embedded in
  every envelope.
- Idempotent retries via `--idempotency-key`.
- SBOM + SLSA L3 + cosign signature on every release artifact.

## Quarterly refresh checklist (operator runbook)

1. Re-read each competitor's CHANGELOG since the last refresh.
2. Update version markers (e.g. Playwright MCP 0.0.x → ?, Puppeteer
   major bumps, Scrapling minor bumps, Crawl4AI breaking changes).
3. Re-confirm every "yes" cell against current behavior.
4. Re-confirm the **≥ 1 losing or tying cell per row** invariant — if any
   row goes all-rev_scraping-wins, the row is poorly chosen and must be
   rewritten or removed.
5. Bump the date at the top + the "next due" date.
6. Sync to `docs/book/src/en/landscape.md` (this file is the source of
   truth; `docs/book/src/en/landscape.md` is regenerated by `cp`).
