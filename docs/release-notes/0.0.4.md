# rev_harness 0.0.4 — Vendoring 構造防御 (canonical-guard + doctor)

リリース日: 2026-05 (PR-B 完了時点)
Plan 参照: `docs/plans/2026-06-agent-sdk-migration/plan-v3-final.md` PR-B

## 概要

外部リポへの vendored copy 経由で wrapper が実行されることによる
意図しない Agent SDK 課金・古い動作の混在を構造的に防ぐため、
canonical root 判定ガードを追加した。

## 主な変更

- `scripts/_canonical-guard.sh` 新規
  - `rev_harness_assert_canonical_root` を提供
  - 起動位置が `$HOME/dev/rev_harness` (または `REV_HARNESS_CANONICAL_ROOT`)
    に一致しない場合 `exit 70` で refuse
  - `REV_HARNESS_VENDOR_CHECK=warn` でソフトモード (deprecated、将来 minor で削除)
- `scripts/claude-wrapper.sh` / `scripts/codex-wrapper.sh`
  - 起動直後に canonical-guard を source して assert
- `scripts/harness-doctor.sh` 拡張
  - vendored copy 検出、canonical root 解決、shim-hits.log 経路の表示
- `docs/inventory-vendored-copies-2026-05.md` 新規
  - Discovery 棚卸結果のスナップショット

## 互換性

- canonical install (`~/dev/rev_harness`) からの起動は無影響
- 別パスにクローンしている場合は `REV_HARNESS_CANONICAL_ROOT` を export
- CI runner 向けの env wiring は 0.0.6 で対応 (`github.workspace` を経路指定)

## アップグレード手順

1. `git pull`
2. `bash scripts/harness-doctor.sh` で vendored 警告がないか確認
3. 警告が出た場合は `docs/adoption-guide.md` の「canonical install の固定方法」を参照

## 既知の制限

- exit 70 は sysexits.h EX_SOFTWARE 相当。CI 統合では env で明示する必要あり
