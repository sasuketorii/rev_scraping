# rev_harness 0.1.0 — de-overkill BREAKING release

リリース日: 2026-06-09
Slice 参照: `d7f3e5e..3da73ff`

## 概要

RevHarness の semantic surface を de-overkill した BREAKING release。
dual semantic backend は Rust-only に統合し、Node TypeScript
`semantic-mcp-server` は削除した。

方針は asymmetry principle: indexing は demote / de-duplicate するが、
raw-read-first、deterministic gates、dual-review、security/privacy guards は
維持する。semantic/tree-sitter indexing は context acceleration のための
opt-in assistance であり、acceptance authority ではない。STALE な semantic
state は fail closed として扱う。

## 主な変更

- Node TypeScript `semantic-mcp-server` を削除し、Rust `semantic-mcp`
  backend のみに統合
- `REV_HARNESS_ALLOW_NODE_SEMANTIC` を fail-closed no-op 化
  (Node backend は復元されない)
- semantic/tree-sitter indexing を first-class default から opt-in に降格
- adopter manifest を Rust-only に更新し、`node_db` を削除
- review round-cap policy を追加
- `scripts/codex-wrapper.sh` に transient retry / timeout を追加
  (timeout exhaustion は reserved exit `75`)
- gate cleanup portability のため `/bin/rm` 経路を明確化

## 互換性

この release は pre-1.0 SemVer に基づく minor bump の BREAKING change。
`0.0.x` adopter は Node semantic fallback が存在する前提で運用できない。
`REV_HARNESS_ALLOW_NODE_SEMANTIC` を設定しても Node backend は有効化されない。

## アップグレード手順

1. Rust toolchain が利用可能であることを確認
2. `harness-rust/` から `cargo build -p semantic-mcp` で Rust semantic
   backend を build
3. `bash scripts/rev-harness-adopter-setup.sh` を再実行し、Rust-only
   manifest と launcher wiring を更新
4. `semantic-mcp-server`、`node_db`、Node fallback、または
   `REV_HARNESS_ALLOW_NODE_SEMANTIC` に依存した運用を削除
5. semantic/tree-sitter indexing は opt-in assistance として扱い、
   raw reads と deterministic gates を acceptance authority とする
