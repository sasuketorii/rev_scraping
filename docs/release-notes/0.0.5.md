# rev_harness 0.0.5 — 報告信頼性 (codex-job.sh)

リリース日: 2026-05
Plan 参照: `docs/plans/2026-05-reporting-reliability/plan-v4-final.md`

## 概要

Codex 経路のジョブ実行において、開始・完了・失敗の各タイミングで
構造化レポート (JSONL) を残す `scripts/codex-job.sh` を導入。
shim-hits.log と組み合わせて、後続の中間レビューや PR-D ゲート判定で
「どの caller が何回 wrapper を経由したか」を再構築可能にした。

## 主な変更

- `scripts/codex-job.sh` 新規
  - ジョブ ID を発行し、`REV_HARNESS_SHIM_JOB_ID` を export して子プロセスへ伝搬
  - 終了コードに応じた完了レポートを `~/.rev_harness/job-reports/` に追記
  - canonical-guard 統合済
- `scripts/_shim-log.sh` 互換変更
  - `REV_HARNESS_SHIM_JOB_ID` が set されている場合のみ JSONL に `job_id` フィールドを付与
  - 未 set の場合は従来の 6 フィールドを維持 (backward compatible)
- `docs/shim-spec.md` 更新
  - `job_id` オプショナルフィールドを正式に記述

## 互換性

- shim-hits.log の既存 reader は壊れない (オプショナルキー追加のみ)
- codex-job.sh は新規スクリプトであり既存呼出への副作用なし

## アップグレード手順

1. `git pull`
2. Codex 経路のラッパーを `scripts/codex-job.sh` 経由に差し替えると job_id 計測が有効化
3. レポートは `~/.rev_harness/job-reports/<date>/<job_id>.jsonl`

## 既知の制限

- job-reports のローテーションは別途運用 (本リリースには未同梱)
- shim-hits.log のローテーションは 0.0.6 に同梱
