## Reference (ExecPlan v1.2.0 rev1, lines 64-71 + DECISION D2)

**Adopt Plan B's quad-state `DisplayMode` enum** with Plan A's auto-resolution table.

### Quad-state enum
```rust
#[derive(clap::ValueEnum, Clone, Copy, Debug, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum DisplayMode {
    Auto,      // resolve at runtime (default)
    Headed,    // force headed Chrome
    Headless,  // chromiumoxide HeadlessMode::New
    Xvfb,      // headed Chrome under `xvfb-run`
}
```

### CLI surface on `rev-auth login` (LoginArgs)
- `--display <auto|headed|headless|xvfb>` (env `REV_AUTH_DISPLAY`, default `auto`).
- `--headless` boolean shortcut → equivalent to `--display headless`.
- `--xvfb` boolean shortcut → equivalent to `--display xvfb`.
- Legacy alias env `REV_AUTH_HEADLESS=1` is honoured (maps to `--display headless`) with a one-line `eprintln!` deprecation warning (deprecation table row from ExecPlan §G).

### Resolution table (`DisplayMode::Auto` only)
| OS | DISPLAY env | xvfb-run present | Resolved |
|----|-------------|------------------|----------|
| macOS | n/a | n/a | `Headed` |
| Linux | non-empty | n/a | `Headed` |
| Linux | empty/unset | yes (and operator opted in via env `REV_AUTH_AUTO_XVFB=1`) | `Xvfb` |
| Linux | empty/unset | no (or opt-in off) | `Headless` (with `eprintln!` warn line) |

Implementation: `fn resolve_display_mode(env: &impl EnvLookup, os: TargetOs) -> DisplayMode`.
Use a small `EnvLookup` trait (`fn get(&self, key: &str) -> Option<String>`) so tests can inject env without `std::env::set_var` races.

### `BrowserConfig` integration
Modify `build_chrome_config_with_vpn` (or split into a new fn) so it accepts `DisplayMode`:
- `Headed` and `Xvfb`: keep `.with_head()` (existing behaviour). For `Xvfb`, additionally require `xvfb-run` on `PATH`; if missing, return `EXIT_CHROME_NOT_FOUND` with a clear message. For `Xvfb`, spawn Chrome through `xvfb-run -a --` (use a wrapper script path or set env). Minimal approach: detect `xvfb-run` and document that the operator runs `xvfb-run -a rev-auth login ...` themselves — but we still need a code path that *records* the chosen mode in audit log and refuses headless `with_head()`. Pick the more conservative path: when `DisplayMode::Xvfb` is chosen, leave `.with_head()` AND assert `xvfb-run` is on PATH (error-out if not). Do **not** auto-spawn xvfb-run as a child process in this slice — that belongs to P10.4.
- `Headless`: DROP `.with_head()` (chromiumoxide defaults to headless). Add `.arg("headless=new")` to force the New Headless engine. Confirm no `with_head()` is called.

### macOS regression guard (Plan A)
Add a compile-time-evaluated assertion that on `target_os = "macos"`, an explicit `--display headless` is honoured but `Auto` always resolves to `Headed`. Express this with a `#[cfg(test)]` test, not `compile_error!`.

### Audit log
