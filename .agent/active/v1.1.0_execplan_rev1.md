# rev_scraping v1.1.0 GA ExecPlan rev1 (Synthesis of Plan A + Plan B)

> **Status:** Design only. No source files modified.
> **Architect:** Synthesis agent (neutral merge of Plan A: Claude opus-4.7-high / Plan B: Codex gpt-5.5-high).
> **Date:** 2026-05-18 JST
> **Predecessor:** v1.0.0-dev (459 PASS, observed 11 workspace crates, 3 binaries, Phase 1-9 complete).
> **Goal:** Ship rev_scraping v1.1.0 as a disciplined small-team / Linux-first / CI-deterministic GA. Backward-compatibility (config, recipes, auth profiles, audit log) is a hard constraint.
> **Non-goal:** Broad commercial distribution, residential proxies, GUI, Windows native, brew/notarization. All deferred to v1.2+.

This rev1 reconciles two independently authored plans. Plan A (600 lines, MUST=6 / SHOULD=7 / DEFER=6) emphasised CI determinism and Linux/CI as the critical path. Plan B (1173 lines, MUST=8 / SHOULD=10 / DEFER=10) added repo-audit, naming-decision, soak-test, and supply-chain workflow YAML detail. The synthesis adopts B's wider MUST surface (B7 docs as MUST, B8 naming as MUST), B's 7-day soak, and B's CI YAML (matrix MSRV + stable). It adopts A's clean §K/§O/§R partitioning, A's `#[ignore]` split convention, A's deterministic axum fixture for B3, and A's `stealth-measure` recommendation as optional. Where the plans diverge on numbers (MSRV, alias count, etc.), the merged plan records both and recommends per-item.

## 0. Executive design summary

v1.0.0-dev shipped the complete feature surface. What is missing for GA is **operational maturity**:
1. Verified hotfix-2 (cookie order, no dialog) on macOS + Linux.
2. `auth login --allow-no-vpn` parity with spider.
3. Real-run E2E across ≥ 3 authorized sites (fixture-server + live).
4. Linux Ubuntu-22.04 first-class with Chrome path / keyring fallback / Docker VPN.
5. CI deterministic green on a 2-OS × 2-toolchain matrix with security gates.
6. Distribution docs (README §15–§20, CHANGELOG, SECURITY, CONTRIBUTING, CODE_OF_CONDUCT).
7. Workspace/crate/binary naming reconciled (README claims 9 crates; actual 11).
8. 7-day soak test.

Wall-day estimate: serial ~14 engineer-days; with 3 engineers ~7 wall-days for engineering, plus 7 wall-days soak (overlap allowed). Critical path: B5 Linux + P13 soak.

No new mandatory crate. Optional `stealth-measure` deferred to SHOULD or v1.1.1.

## B. MUST items — design detail

### B1. hotfix-2 re-verification — **cookie order + dialog suppression**

- Plan A says: focus on Chrome dialog suppression flags survival; add `auth doctor` subcommand + `auth_login_no_dialog_macos` test.
- Plan B says: focus on cookie merge replay order (`__Host-`, `__Secure-`, `SameSite=None`, host-only); add `merge_cookie_replay_order` API + unit test.
- 統合判断: **両方採用**. The hotfix-2 series had two distinct fixes (dialog + cookie order). Both regressions must be locked. Deliverables: (a) `auth doctor` per A, (b) `merge_cookie_replay_order` unit test per B, (c) live replay test gated by `REV_LIVE=1`. Effort: 0.75 wall-day.

### B2. `auth login --allow-no-vpn` / `--require-vpn`

- Plan A says: refactor to consume `VpnRequirementFlags` shared struct; audit log records `vpn_skipped_reason`.
- Plan B says: `clap::Args` with `conflicts_with`; `REV_SCRAPING_REQUIRE_VPN=1` env cannot be loosened by `--allow-no-vpn`.
- 統合判断: **両方採用**. A's shared struct + B's `conflicts_with` + B's env-override-cannot-loosen rule. Audit log records skip reason. Effort: 0.5 wall-day.

### B3. `spider --use-auth` real-site E2E

- Plan A says: prefer self-hosted axum fixture (deterministic CI) + live example/DaiGo (manual dispatch); 1 fixture + 1-2 live.
- Plan B says: live manifest with ≥ 3 sites (CF-protected / SPA / SSR), each with `assert_selector`; no fixture-server.
- 統合判断: **両方採用 (merged)**. CI runs A's axum fixture (deterministic; HttpOnly + SameSite=None+Secure via rcgen self-signed cert). Manual-dispatch `e2e-manual.yml` runs B's 3-site matrix via `tests/live_manifest.example.toml` (real values not committed). Site categories per B: 1× CF-protected, 1× SPA, 1× SSR. Effort: 1.5 wall-days (A's higher estimate; covers both fixture and manifest scaffolding).

### B4. CI deterministic green

- Plan A says: remove `continue-on-error`, pin toolchain via `rust-toolchain.toml`, add `cargo fmt --check`, `cargo-deny`, weekly `cargo audit` cron, per-job timing artifact.
- Plan B says: matrix `macos-14`/`ubuntu-22.04` × `stable`/`1.83.0` (MSRV), add `gitleaks`, `SPDX`, docs build, release dry-run.
- 統合判断: **両方採用**. Full matrix per B (2 OS × 2 toolchain). All A's gates plus B's `gitleaks` and `SPDX`. `continue-on-error` removed from GA-required jobs; flaky tests moved to `e2e-manual.yml`. Effort: 1.5 wall-day (B's estimate).

### B5. Linux Ubuntu 22.04 first-class

- Plan A says: Docker repro first (`docker/linux-ci/Dockerfile`), CI matrix promotion, Chrome path probe, keyring → libsecret + passphrase fallback, `xvfb-run` for headed-on-Linux.
- Plan B says: Chrome probe order including snap (deprioritised), `libsecret-1-0`+`dbus-user-session`+`gnome-keyring` packages, Docker VPN `--cap-add=NET_ADMIN --device=/dev/net/tun`, headless server passphrase mode.
- 統合判断: **両方採用**. A's Dockerfile + B's snap caveat (deprioritised). Plan B's Chrome path order is more complete (8 entries including macOS at position 8). Adopt B's keyring decision: **no implicit plaintext fallback; show clear error + passphrase prompt** (Q11). Effort: 2.5 wall-days (A's higher; B underestimates at 1.25d).

### B6. Obscura cookie injection + persistence

- Plan A says: `obscura_cookie_injection_member_page` integration test reusing axum fixture; gated by `REV_SCRAPING_RUN_OBSCURA=1`; possibly small `cdp_shim` patch.
- Plan B says: persistence verification after browser restart, with extension enabled/disabled comparison, `CDP Network.getAllCookies` redacted metadata.
- 統合判断: **両方採用**. A's E2E test + B's restart-persistence + extension-toggle comparison. Effort: 1.25 wall-days.
