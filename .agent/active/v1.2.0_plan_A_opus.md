## 0. Executive design summary

v1.1.0 GA hardened the **engine**: stealth, VPN, auth, recipes, MCP transport, Linux parity, CI determinism. v1.2.0 hardens the **surface**: how a human operator brings a VPS up; how an LLM agent introspects and recovers from errors; how a Hermes-class supervisor calls into the toolset; how `policy.toml` is migrated safely.

Four audits converge on one structural insight: **the work that remains is overwhelmingly additive — new flags, new subcommands, new schema fields, new manifests, new docs.** No core crate redesign. The risk surface is therefore *backward-compatibility integrity* (v1.1 configs MUST load unchanged) and *test gate inflation* (≥ 600 PASS).

Wall-day estimate: 24 engineer-days serial; **with 3 engineers ~10 wall-days** (critical path = P10a-VPS + P10e-Agentability; Hermes adapter is independent and can ship parallel). No new mandatory crate. Two new optional artefacts: `dist/systemd/` (text files only) and `docs/integration/hermes/` (template Python, not built by Cargo).

The single highest-leverage decision (DECISION-1): **does v1.2.0 add a `stealth-mcp` TCP/Unix-socket transport, or strictly remain stdio with documented SSH-tunnel recipe?** Plan A recommends **stdio-only** (preserves the audited trust boundary; defer transport rewrite to v1.3).

## B. VPS productionisation design (P10a)

### B.1 `--headless` flag for rev-auth

**Surface change** (`crates/stealth-auth/src/bin/rev_auth.rs`):

- New CLI flag `--headless[=auto|true|false]` (clap `ArgAction::Set` with `Option<HeadlessMode>` enum).
- New env `REV_AUTH_HEADLESS={0|1|xvfb|auto}` (precedence: CLI > env > default).
- `auto` resolves to: `false` on macOS / `true` when no DISPLAY on Linux / `xvfb` if `xvfb-run` on PATH and `--remote-display` requested.
- Default value: **unchanged** — headed on operator laptop. This is a critical compatibility constraint.

**Wiring** at `rev_auth.rs:530`:

```text
let mut builder = BrowserConfig::builder()
    .chrome_executable(chrome_bin);
match resolve_headless_mode(cli.headless, env_headless, target_os) {
    HeadlessMode::Headed   => builder = builder.with_head(),
    HeadlessMode::Headless => builder = builder.headless_mode(HeadlessMode::New),
    HeadlessMode::Xvfb     => builder = builder.with_head(), // process is wrapped by xvfb-run externally
}
```

**Tests** (`#[cfg(target_os = "linux")]`):

- `headless_explicit_false_still_uses_with_head` (regression guard).
- `headless_auto_no_display_chooses_headless` (sets `DISPLAY=`, asserts Headless branch).
- `headless_env_overrides_default_but_not_cli` (CLI precedence).
- macOS retains existing `headed_launch_uses_with_head_flag`.

Reuse macOS-side test by parametrising; do NOT delete the existing assertion.

### B.2 Local-capture → VPS export protocol (documented, zero code)

`docs/deploy/vps.md` § "Auth bootstrap (Track 1)":

1. Operator runs `rev-auth login --profile <P>` on workstation (works today).
2. `scp -p ~/.config/rev_scraping/auth/<P>.enc vps:~/.config/rev_scraping/auth/<P>.enc`.
3. Set `REV_SCRAPING_AUTH_PASSPHRASE` on the VPS via `LoadCredentialEncrypted=` (B.4).
4. `aad_context` (AAD binding) MUST be identical on both sides — documented inline with worked example.

This is **Track 1: zero code, best security**. The `--headless` flag (B.1) is the fallback (Track 2) for sites that IP-pin sessions.

### B.4 `LoadCredentialEncrypted=` integration

`stealth-auth::keystore.rs` already reads `REV_SCRAPING_AUTH_PASSPHRASE` from env. Under systemd ≥ 250 with `LoadCredentialEncrypted=auth-pass:...`, the credential is exposed at `$CREDENTIALS_DIRECTORY/auth-pass`. The unit's `ExecStartPre=` reads the file into env:

```text
ExecStartPre=/usr/bin/env REV_SCRAPING_AUTH_PASSPHRASE=$(cat ${CREDENTIALS_DIRECTORY}/auth-pass) /bin/true
```

Plan-A preferred alternative: a 30-line `stealth-cli` change that natively reads `$CREDENTIALS_DIRECTORY/auth-pass` if set, removing the env-var hop. **Recommended; raises security floor.** Tracked as v12-M2 sub-task.

### B.5 `doctor --vps`

`rev-stealth doctor --vps` extension (additive flag; no existing flag retired):

- LUKS mount: `findmnt /var/lib/rev_scraping` → check `OPTIONS` for `crypt` token.
- gluetun health: `docker compose ps --format json` (already used in `vpn-rotate`); reused.
- DISPLAY heuristic: if `DISPLAY` unset AND any auth profile present AND `--headless` not opted-in → **warn**, not fail.
- Keyring/passphrase resolution: print which `KeySource` would be selected (`Keyring` / `Passphrase` / `Error`).
- `.env` perm check: walk `[ ".env", ".env.local", "policy.toml", "authorized.toml" ]`; warn if mode > 0600.
- systemd: `systemctl --user is-active rev-scraping-vpn.service` (read-only).

Output: JSON (default `--json`) and human (default sans flag). Exit 0 on all-pass, 1 on warn, 7 on leak-class fail (mirrors existing doctor convention).

### C.2 Subprocess + restart-with-backoff

`mcp_client.py` (~150 LOC):

- `StealthMcpClient.shared()` — lazy singleton, fork-safe (init guarded by `os.getpid()` cache).
- `subprocess.Popen([REV_SCRAPING_MCP_BIN], stdin=PIPE, stdout=PIPE, stderr=PIPE, text=True, bufsize=1, env=<whitelist>)`.
- JSON-RPC framing: **NDJSON** (confirmed against `crates/stealth-mcp/src/server.rs:50` `run_stdio` line-buffered read). If Content-Length framing is detected later, swap reader.
- Response correlation by `id`; `Dict[id → Future]`; daemon thread reads `stdout.readline()` loop.
- `_drain_stderr` daemon thread mirrors `rev_contact_invoke.py:44`; rate-limited (1 line / 100 ms) into Hermes log.
- Restart-with-backoff: 1 s → 5 s → 30 s; circuit-break after 3× failures in 5 min; surfaces `kind="child_unavailable"`.

### C.3 Tool registration fan-out

`__init__.py::register(ctx)`:

1. Acquire shared client; call `tools/list` once (cached for plugin lifetime).
2. For each tool `t` in the 15-tool catalog (or whatever the v1.2.0 server advertises):
   - Hermes name: `rev_{t.name}` (prefix prevents future collision).
   - Schema dict: `{ name, description, parameters: t.inputSchema, outputSchema: t.outputSchema }`.
   - Handler: closure capturing `(client, t.name)` → returns JSON string (Hermes convention).
   - `check_fn`: `lambda: client.is_alive() and os.path.isfile(REV_SCRAPING_MCP_BIN)`.

### D.5 Backup, diff, rollback

`stealth-cli/src/config_io.rs` (new module):

- `atomic_write_with_backup(path, contents)`:
  1. Compute `sha256(contents)`; compare to on-disk; if identical, **skip write**, return `Unchanged`.
  2. Copy current file to `<path>.bak.<epoch_ms>`; chmod 0600.
  3. Write to `<path>.new`; fsync; rename to `path`.
  4. Audit-log: `{event: "config_write", path, sha256_before, sha256_after, actor: "CLI"|"MCP", profile}`.
- `gc_backups(path, keep=5)`: sweep older `*.bak.*` snapshots.
- `diff(path)`: load on-disk + effective; produce `similar`-crate unified diff; colour security-relevant fields (any `*_secret`, `passphrase`, `url`, `vpn_user`, `vpn_password`) red.

## E. Agentability 強化 (P10d)

### E.1 outputSchema + additionalProperties:false

`crates/stealth-mcp/src/tools.rs::tool_definitions()` refactor:

- Each tool entry gains `output_schema: &'static str` (JSON-Schema string, `include_str!` from `docs/json-schemas/{tool}.output.json`).
- Each input schema gains `"additionalProperties": false` at root and all nested objects.
- Each property gains `description` (one-line; "what / when / why").
- URL fields gain `"format": "uri"`; hostname fields `"format": "hostname"`; UUID fields `"format": "uuid"`; timestamps `"format": "date-time"`.
- Enums populated: `vpn_rotate.region`, `recipe_propose_endpoint.endpoint.http_method`, `auth_list.status`.
- Bounds: `spider.threshold` adds `minimum:0, maximum:1`.
- Length caps: every free-form string field gets a sane `maxLength` (default 4096; `url_pattern` 1024; `payload` 1 MiB).
- `examples: []` array with 1-3 entries per tool.

A `tests/strict_mode_compat.rs` integration test loads every input+output schema through a strict-mode validator (the `jsonschema` crate with `Draft7` and `additionalProperties=false` enforced) and asserts pass.

### E.2 Error envelope standardisation

```rust
pub struct ErrorEnvelope {
    pub kind: ErrorKind,         // enum, serde tag = "kind"
    pub message: String,         // human
    pub retryable: bool,
    pub retry_after_ms: Option<u64>,
    pub hint: Option<String>,    // ONE actionable sentence
    pub schema_ref: Option<String>,  // points at tool name when MissingField
    pub correlation_id: Option<String>, // echoes JSON-RPC id
}

pub enum ErrorKind {
    AupBlocked, Ssrf, VpnPoolEmpty, VpnLeak, VpnRotationFailed,
    CfUnsolved, CfChallenge,
    RelocateMiss, RelocateAmbiguous,
    TransientNetwork, PermanentRemote, ProxyExhausted,
    Http429, Http5xx,
    AuthExpired, AuthMissing, AuthAlreadyLoggingIn,
    InvalidParams, MissingField, UnknownField,
    ChildUnavailable, Timeout, ChildCrash,
    ConfigInvalid, ConfigSchemaTooNew,
    InternalError, // catch-all; logged
}
```

Embedded in BOTH:
- Success-shape envelope: `{ ok: false, error: ErrorEnvelope, ... }`.
- JSON-RPC error: `JsonRpcError { code, message, data: ErrorEnvelope }`.

Exit codes (`crates/stealth-cli/src/commands/exit.rs`) map 1-to-1 to `ErrorKind` (table maintained in `commands/exit.rs` doc comment).

### E.3 Rate-limit runtime

New module `crates/stealth-core/src/rate_limit.rs`:

- `HostTokenBucket { host: String, capacity: u32, refill_per_sec: f64, ... }`.
- Per-host buckets owned by a process-wide `RateLimiter` (`once_cell::sync::Lazy`).
- Config sources (priority): CLI `--max-rps` / `--burst` > `SiteRecipe.rate_limits.{recommended_rps, burst}` > defaults (1 rps / 3 burst).
- On HTTP 429 / 503:
  - Parse `Retry-After` (seconds or HTTP-date).
  - Sleep `retry_after + jitter(±20%)`.
  - Decrement bucket; surface `retry_after_ms` in `ErrorEnvelope`.
- Honoured by both `spider` (CDP path) and `fallback_http` (reqwest path).
- Hooked at `Browser::navigate` and `reqwest::get` wrappers. Existing call-sites get `?` propagation through `RateLimitError`.

Tests:
- `single_host_bursts_then_blocks` (deterministic clock via `tokio::time::pause()`).
- `respect_retry_after_seconds_form`.
- `respect_retry_after_http_date_form`.
- `jitter_within_20pct_band`.

### E.4 Idempotency keys

`recipe_propose_endpoint`:
- Dedupe key: `(domain, purpose, path, http_method)`. If exists, return existing entry's `index` + `{deduped: true}`.
- Optional client-supplied `idempotency_key`: cached in `~/.rev_scraping/idempotency.jsonl` (TTL 24 h); duplicate key returns original response.

`recipe_import`:
- Compute `sha256` of payload; if last-imported equals current, return `{ no_op: true, sha256 }`.

`auth_login_start`:
- Per-profile file lock (`~/.rev_scraping/auth/<profile>.lock`, advisory `fcntl`); second concurrent start → `ErrorKind::AuthAlreadyLoggingIn`.

### E.5 progressToken + HTML auto-spill

`progressToken` (MCP draft):
- On `tools/call`, if `params.progressToken` present, server emits `notifications/progress` lines on stdout interleaved with the eventual result (line-buffered NDJSON; MCP-spec-compliant interleaving via `id` separation).
- Long ops emitting progress: `spider` (per major step: AUP gate / VPN selection / navigate / CF eval / dump), `auth_login_complete` (5 s heartbeat), `recipe_export` (per-recipe streamed).

HTML auto-spill (`spider`):
- Threshold env `REV_SPIDER_HTML_INLINE_MAX_BYTES` (default 262_144 = 256 KiB).
- If `html.len() > threshold` AND `--dump-html <path>` not set, auto-write to `~/.rev_scraping/spool/<session_id>.html` (0600), set `dump_path` field, replace inline `html` with `html_preview` (first 4 KiB).
- New envelope field `content_trust: "untrusted"` on `html`/`html_preview`.

### E.6 session_id + session_show

- Every MCP tool gains an optional top-level `session_id` arg (`format: uuid`). If absent, server mints one (existing spider behaviour generalised).
- Every tool's `structuredContent` echoes `session_id` + `correlation_id` (= JSON-RPC `id`).
- Session log: append `{ts, session_id, tool, args_redacted, exit_code, elapsed_ms}` to `~/.rev_scraping/sessions/<session_id>.jsonl` (0600).
- New tool `session_show { session_id }` returns the full event stream + summary (tools called, durations, error counts).

### E.7 `--log-json` + `tool_latency_ms`

- `--log-json` global flag (and `REV_LOG_JSON=1`) switches `tracing_subscriber::fmt()` to `.json()` formatter.
- Every MCP `structuredContent` adds `tool_latency_ms` (measured at server entry/exit) and `started_at_iso` (RFC3339 UTC).
