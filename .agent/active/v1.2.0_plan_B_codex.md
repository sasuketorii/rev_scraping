Status: design-only execution plan.
Repository: `$REPO_ROOT`
Branch baseline: `main` at `67665db` (`v1.1.0` GA, 519 PASS).
Objective: make rev_scraping plug-and-play for production Linux VPS use, HermesAgent integration, modern CLI config management, and 2025-grade MCP agent contracts.

## A. Scope Partition
v1.2.0 is a production-readiness release, not a stealth-engine rewrite.
The release must make the existing v1.1.0 capabilities deployable and operable by an expert or agent without hand-editing hidden state.
In scope for v1.2.0:
| Area | v1.2.0 commitment | Acceptance shape |
|---|---|---|
| Linux VPS | Headless auth mode, Xvfb fallback, systemd units, credentials, journald, limits | Ubuntu 22.04/24.04 smoke passes without desktop session |
| HermesAgent | Adapter plugin scaffold and contract tests | `~/.hermes/plugins/rev-scraping-mcp/` loads and registers tools against mock Hermes |
| Config UX | `rev-stealth config` command family | Operators can init, inspect, validate, edit, migrate, and rollback safely |
| MCP agentability | strict schemas, output schemas, error envelopes, rate limits, progress, cancellation | MCP conformance tests validate every advertised tool |
| Documentation | production docs and references | README links to VPS, Hermes, Config, MCP guides |
| Compatibility | v1.1.0 paths and tool names continue | Existing scripts keep working with deprecation notices only |
| Tests | >= 600 PASS target | New category gates in CI and local verification matrix |
Deferred to v1.3+:
| Deferred item | Reason |
|---|---|
| Public internet MCP gateway | Requires authn/authz, replay defense, abuse controls, and threat-model expansion |
| Native HermesAgent core MCP loader | Belongs to HermesAgent; v1.2.0 ships an update-safe plugin adapter |
| Cloud provider Terraform | Avoid provider lock-in; docs cover reference VPS runbooks |
| Multi-VPS orchestration | v1.2.0 targets one production host first |
| Distributed spider queue | Requires datastore and scheduler choices outside readiness scope |
| Full OpenTelemetry collector stack | JSON logs and journald first; metrics exporter can follow |
| Hosted browserless/Selenium auth capture | Third-party browser custody weakens the credential threat model |
| Secret-manager integrations beyond systemd credentials and env placeholders | Vault/1Password URI resolvers can land in v1.3 after config core stabilizes |
| GUI/TUI config editor | `config edit` invokes `$EDITOR`; richer UI can wait |
| Windows production service support | Linux VPS is the first-class v1.2.0 platform |

    pub requires_display: bool,
    pub chrome_args: Vec<String>,
    pub warning: Option<String>,
}
pub fn resolve_display_mode(

Display resolution policy:
| Input | Result |
|---|---|
| `--display=headed` | Use `BrowserConfig::builder().with_head()` and require `DISPLAY` on Linux |
| `--display=headless` or `--headless` | Use chromiumoxide headless mode and no X server |
| `--display=xvfb` or `--xvfb` | Launch through Xvfb wrapper or refuse if `xvfb-run` unavailable |
| `--display=auto` on Linux with `DISPLAY` unset | Use headless, print one warning |
| `--display=auto` on Linux with `DISPLAY` set | Use headed |
| `--display=auto` on macOS | Preserve headed default |
Chrome config API starting point:
```rust
pub fn build_chrome_config_with_vpn_and_display(
    chrome_bin: &std::path::Path,
    user_data_dir: &std::path::Path,
    vpn_selection: Option<&vpn_rotate::instance_pool::VpnInstance>,
    display: &DisplayDecision,
) -> Result<chromiumoxide::BrowserConfig, String> {
    let mut builder = chromiumoxide::BrowserConfig::builder()
        .chrome_executable(chrome_bin)
        .user_data_dir(user_data_dir)
        .window_size(1280, 800)
        .arg(("disable-blink-features", "AutomationControlled"))
        .arg("no-first-run")
        .arg("no-default-browser-check");
    builder = match display.mode {
        AuthDisplayMode::Headed | AuthDisplayMode::Xvfb | AuthDisplayMode::Auto => builder.with_head(),
        AuthDisplayMode::Headless => builder.with_headless(),
    };
    if let Some(selection) = vpn_selection {
        let proxy_server = format!("http://127.0.0.1:{}", selection.http_proxy_port);
        builder = builder
            .arg(("proxy-server", proxy_server.as_str()))
            .arg(("proxy-bypass-list", "127.0.0.1;localhost"));
    }
    builder.build()
}
```

Transport decision:
Use long-lived stdio JSON-RPC over newline-delimited JSON.
Rationale:
| Option | Decision | Reason |
|---|---|---|
| stdio JSON-RPC NDJSON | Use | Existing server contract, no network surface, fast local IPC |
| Content-Length MCP framing | Defer | Current protocol code is line-delimited; adapter must match reality |
| WebSocket | Defer | Adds authentication and exposure problems |
| HTTP wrapper | Reject for v1.2.0 | Duplicates transport and expands attack surface |
| Per-call CLI subprocess | Reject for primary path | Slower and loses MCP-native schemas/progress |
